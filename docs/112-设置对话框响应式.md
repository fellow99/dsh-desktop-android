# 112 · 设置对话框响应式（窄屏栏目上移）

> 日期：2026-11-01 ｜ 平台：Android（WebView）｜ 上游：`dsh-v0.2.1-rc.5` ｜ 实现：**纯 CSS 注入（上游零补丁）**
> 关联：111（同期真机验证引擎 26.13.0 / minSdk 26）

## 一、问题与现状（真机 DOM 实测）

设置对话框是左右两栏。手机竖屏（WebView 视口 ≈393px）下：

| 元素 | 结构 | 尺寸 |
|---|---|---|
| `DIV[role="dialog"]`（panel） | flex **row** | 宽 **345** |
| `NAV`（左栏目） | flex column（`navTitle` 设置 + `navList` 六个 tab） | 宽 **188**（≈54%） |
| 内容区（nav 的兄弟） | — | 仅 ~157，被挤压 |

上游类名是 CSS-modules **哈希前缀**（`JnlPgW_nav/_panel/_navList/_navCell`，上游重建即变）；
上游**没有**把「nav 位置/形态」暴露成 slot，也无现成响应式。

## 二、方案评估（四选一）

| 方式 | 零补丁(C1) | 抗升级 | 上移 tabs | 下拉 | 结论 |
|---|---|---|---|---|---|
| **A. 下游注入 CSS**（`webServer index-inject` 推 `{kind:'style'}`） | ✅ | ✅（语义选择器） | ✅ | ❌ | **采纳** |
| B. 客户端 seam 插件（运行时注入 CSS/JS） | ✅ | ✅ | ✅ | ✅(需 JS) | 备选（若要下拉） |
| C. 上游源码补丁（materialize patch） | ❌ | ❌ | ✅ | ✅ | 不采纳（违 C1、易随上游漂移） |
| D. WebView 缩放 viewport | ✅ | ✅ | ⚠️牺牲观感 | ❌ | 不采纳（副作用大） |

**采纳 A**：`webserver/index-inject` 是 dsh 一等注入口（`@dsh-android/branding` 注入 `HERO_CSS` 同款），
纯 CSS 即可实现「tabs 上移」，且用语义选择器抗上游类名哈希变化。

## 三、实现

新增宿主插件 **`@dsh-android/ui-responsive`**（`packages/ui-responsive-android`，`inject=['webServer']`），
在 `webserver/index-inject` 推一条 `style` 行（`RESPONSIVE_CSS`），挂载行见 `@dsh-android/bundle` 的
`cordis.patch.yml`（`ui-responsive-android`）。

### 选择器纪律（抗升级）
只用**语义结构**，不引用哈希类名：
`[role="dialog"]:has(> nav)`（=含直接 nav 子元素的设置面板）、`nav > div:last-child`（tab 列表）、
`nav button`（tab）。`:has()` 依赖 WebView ≥105（G-WV 门禁 ≥110，满足）。规则严格限定该 dialog，
不波及其它弹层；结构不匹配时退回上游原样（不误伤）。

### 规则（`@media (max-width:600px)`）
1. 面板 `flex-direction: row → column`（nav 在上、内容在下）；
2. `nav` 整宽、去右分割线改底边线、高度自适应；
3. `nav > div:last-child`（tab 列表）`column → row`、`overflow-x:auto`（横向可滚动条）；
4. `nav button` 按内容宽度、不换行；
5. 内容区 `flex:1` 拿回整宽并可纵向滚动。

阈值 600px：手机竖屏（~393）触发；手机横屏（~742）、平板、桌面不触发（保持上游左右两栏）。

## 四、真机验证（MIX / Android 8.0 / API26）

| 方向 | 视口 | panel | nav | tab 列表 | 内容区 |
|---|---|---|---|---|---|
| 竖屏 | 392 | **column** | 全宽 345 / 高 109 | **row + overflow-x:auto** | **345 全宽** |
| 横屏 | 742 | row（原样） | 188 column（原样） | column（原样） | — |

注入生效：`document` 内存在含 `DSH_ANDROID_UI_RESPONSIVE` 的 `<style>`。
证据：`logs/20261101-1/evidence/35-settings-responsive-portrait.png`、`36-settings-landscape.png`。

## 五、边界与后续

- 纯 CSS，不改上游源码/业务逻辑；无副作用（规则限定设置面板）。
- 如需「下拉选择栏目」（更省纵向空间）→ 需 JS 交互，届时走 B（客户端插件）。

## 六、补充：左侧边栏窄屏**浮动展开**（不挤占主内容）

> 同一插件 `@dsh-android/ui-responsive`（窄屏媒体查询内追加规则）。

### 现象
手机竖屏（WebView 视口 ~392px）展开左侧菜单后，左栏（宽 280）与主内容并列于 CSS **Grid**（`grid-template-columns:280px 1fr 0`）→ 主内容被压到约 **113px**。右侧栏展开却是全屏/覆盖式（不挤占）。期望：左栏也**浮动覆盖**，主内容保持全宽。

### 关键约束（真机实测）
- 布局是 **CSS Grid**（frame 上通过**内联** `grid-template-columns` 设定三列）——仅把 sidebar 设 `position:absolute` 不够（第一列 280 仍被保留，center 落回该列 → 仍 280）。
- 该 WebView 的 CSS **不支持 `:not(:has(...))` 嵌套**（`querySelectorAll` 报 invalid，整条规则被丢弃）；`CSS.supports` 的简单探测会误报为 true。
- 展开/收起的可靠信号：**展开态才存在** `aria-label="收起侧边栏"` 按钮（收起态是 `打开侧边栏`）。

### 规则（`@media (max-width:600px)`）
```css
/* 展开判定：仅展开态存在的 aria-label（纯 :has(属性)） */
[class*="_frame"]:has([aria-label="收起侧边栏"]) { grid-template-columns: 0px 1fr 0px !important; }
[class*="_frame"]:has([aria-label="收起侧边栏"]) > [class*="_sidebarCol"] {
  position: absolute !important; left:0; top:0; bottom:0; z-index:40; height:100%;
  box-shadow: 0 10px 30px rgba(0,0,0,.45);
}
[class*="_frame"]:has([aria-label="收起侧边栏"]) > [class*="_centerCol"] { grid-column: 1 / -1 !important; }
```
第一列压 0 + 主内容跨满全宽 + 左栏绝对定位浮动。收起态无该 aria → 规则不匹配 → 保持原内联轨道。

### 验证（MIX / API26 竖屏）
| 状态 | grid 列 | 左栏 | 主内容 |
|---|---|---|---|
| 收起 | `56px 336.7px 0` | static，56 | 337（x=56） |
| 展开 | `0px 392.7px 0` | **absolute，280（浮动+阴影）** | **393 全宽**（在后方） |

证据：`logs/20261101-1/evidence/53-left-float.png`（修复前挤占：center 280/右侧空白）、`56-left-float-final.png`（修复后：内容全宽在面板后方）。
